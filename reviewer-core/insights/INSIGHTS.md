## What Works

### 2026-10-08 — Long reference text goes first, the diff last
With the project-context documents placed right before `## Diff to review`, the
General Reviewer on deepseek-v4-flash answered "no diff was provided" and
approved demo PR #3 in 2 of 2 runs (47–234 s). The same agent without documents
found the SSRF in 2 of 2 (16–20 s); with the documents moved to the top of the
user message it found it in 2 of 2 again (24–27 s). Small sample, clear direction:
new long sections belong before the PR material, never between it and the diff.
Evidence: `src/prompt.ts:163`, `test/prompt.test.ts:150`

## What Doesn't Work

### 2026-10-08 — `timeoutMs` does not bound a model call
`OpenRouterProvider` passes `timeout: 90_000` to the openai SDK, but the SDK only
times the request until response headers arrive; the body is read afterwards
with no limit. OpenRouter replies 200 immediately and holds the body open while
the model generates, so a stalled generation never times out, and the structured
retry loop never gets control back. Bounding the call needs an AbortSignal with a
total deadline passed to `chat.completions.create`.
Evidence: `src/llm/openrouter.ts:54`, `src/llm/openrouter.ts:68`

## Codebase Patterns

### 2026-10-08 — Skills are delimited, but not as `<untrusted>`
`INJECTION_GUARD` tells the model to ignore every instruction inside
`<untrusted>` blocks, and a skill is nothing but instructions — wrapped that way
it would be inert. Skills go under `## Skills / rules` as `<skill name="…">`
blocks after `SKILLS_PREAMBLE`, which states what a skill cannot do (change the
output format, severities, security rules, or drop findings). A body cannot
close its own tag. Imported third-party skills are kept safe by the server
(disabled until vetted), not by this wrapper.
Evidence: `src/prompt.ts:16`, `src/prompt.ts:34`, `src/prompt.ts:46`

### 2026-10-08 — Derived intent is untrusted, like the text it came from
The intent block is generated by a model from the author's title and
description, so it inherits their trust level: `<untrusted source="intent">`,
under the same guard. On demo PR #3 the model put "validation of the webhook
URL" into out-of-scope — exactly the SSRF hole — which is why intent may inform
a rationale but never reduce findings.
Evidence: `src/prompt.ts:16`, `src/prompt.ts:153`

### 2026-10-13 — Escape delimiter-closing tags case- and space-insensitively
`wrapUntrusted` replaced only an exact `</untrusted>` and skills only `</skill`; a
document or intent with `</UNTRUSTED>` or `< / untrusted >` passed through, and models
treat those as the same tag. Both now use a regex with `\s*` and the `i` flag; any new
delimiter should do the same.
Evidence: `src/prompt.ts:58`, `src/prompt.ts:79`

### 2026-10-13 — Findings land two lines off: the model counts lines from the hunk header
On demo PR #3 every reviewer put the SSRF finding on `routes.ts:175` (`headers:`); the
`fetch` is on 173. The diff goes into the prompt raw, so the model counts from `@@` and
drifts — grounding still passes, since 175 is a shown line. The risk brief had the same
error and fixed it by prefixing each new-side line with its number (server
`reviews/brief/helpers.ts` `numberedDiff`): two runs then cited 173 exactly. Doing the
same here would change every review prompt, so it was left for a reviewer-core task.
Evidence: `src/prompt.ts:182`, `../server/src/modules/reviews/brief/helpers.ts:48`
