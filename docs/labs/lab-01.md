# L01 — вартість прогонів і знахідки за severity

Перший урок повертає в стартер дві речі: скільки коштує кожен прогін рев'ю і
розбивку знахідок за критичністю. Плюс фундамент для роботи з агентом:
CLAUDE.md, документація пакетів і скіл, що веде інсайти.

## Вартість прогону — лабораторна, [#4](https://github.com/AgentIvan/dev-digest/pull/4)

Вартість видно у списку PR (сума успішних прогонів), на кожній плитці Timeline
і окремим блоком у Trace drawer.

![Колонка Cost у списку PR](https://raw.githubusercontent.com/vbronetskyi/devdigest/pr-assets/lab-1/pr-list-cost.png)

Рахувати нічого не довелося: `reviewer-core` уже отримував від OpenRouter
реальну суму в `usage.cost`, сервер її просто викидав. Тепер вона пишеться в
`agent_runs.cost_usd` у момент завершення прогону. Перерахунок «токени × ціна з
прайсу» я свідомо не робив. На живому прогоні OpenRouter списав $0.000153636 —
саме це число й записалось, — а за прайс-листом вийшло б $0.000514, утричі
більше.

Невідома вартість ніде не перетворюється на нуль: в API це `null`, в інтерфейсі —
«—». Суми до долара показуються трьома значущими цифрами (`$0.000154`), бо
`toFixed(3)` з дизайн-макета перетворив би типовий прогін на `$0.000`.

## Документація для агента

- `CLAUDE.md` у корені — стек, структура, команди, конвенції найменувань і зони,
  яких не можна чіпати (міграції, lock-файли).
- `CLAUDE.md` у кожному пакеті з розділом «Read when», що веде на його `docs/`
  (як влаштовано) і `specs/` (що мусить лишатися правдою).
- Скіл `.claude/skills/engineering-insights`: читає `insights/INSIGHTS.md` пакета
  перед роботою і дописує датовані записи з `file:line` після неї. Нічого не
  переписує — помилкову думку заміщає новим записом.

## Знахідки за severity — домашка, [#5](https://github.com/AgentIvan/dev-digest/pull/5)

У розгорнутій картці прогону під вердиктом — рядок `N CRITICAL · N WARNING ·
N SUGGESTION` і три кнопки-фільтри. Числа рахуються з того ж списку, що й
картки, тож завжди збігаються з тим, що видно нижче.

![Лічильники й фільтри в картці прогону](https://raw.githubusercontent.com/vbronetskyi/devdigest/pr-assets/hw-1/run-card-counts.png)

У списку PR — колонка FINDINGS. Наведення відкриває попап зі знахідками
останнього прогону, лише для читання.

![Попап «N findings in this run»](https://raw.githubusercontent.com/vbronetskyi/devdigest/pr-assets/hw-1/pr-list-findings-preview.png)

Жоден лічильник не звертається до моделі: це групування вже збережених знахідок.

## Insights записуються самі

Опис скіла `engineering-insights` сам по собі спрацьовував ненадійно. Тому
протокол тримають два хуки Claude Code у `.claude/settings.json`. `SessionStart`
запам'ятовує коміт, з якого почалась сесія, і нагадує прочитати insights.
`Stop` порівнює все, що сесія змінила (закомічене теж), і якщо код пакета
змінився, а його `INSIGHTS.md` ні, — повертає агента дописати запис. Сказати
«нічого вартого запису» теж можна: тоді наступна зупинка проходить.

## Як перевірити самому

1. `./scripts/dev.sh`, потім у `server/.env` — `OPENROUTER_API_KEY` і `GITHUB_TOKEN`.
2. Додати репозиторій (свій або цей форк), відкрити PR, **Run Review → all agents**.
3. Подивитись колонки Cost і Findings у списку, Timeline і картки на вкладці
   Agent runs, блок COST у трасуванні (іконка документа на плитці).

Тести: `cd server && pnpm exec vitest run --exclude '**/*.it.test.ts'` і
`pnpm exec vitest run .it.test` (потрібен Docker), `cd client && pnpm test`.

## Що знайшлося по дорозі

Прогнав трьох вбудованих рецензентів на трьох demo-PR:

- **SSRF** у вебхуку (#3) знайшли всі троє.
- **N+1** у зведенні активності (#2) знайшли General і Security, а Performance
  Reviewer — ні. Як з'ясувалось у L02, він не пропустив проблему, а не побачив
  дифф: збережений прогін пише «the diff is not present», хоча в промпті дифф є.
- На чистому #1 General вигадав CRITICAL про роутинг і завалив PR. Коротке
  доповнення до промпту прибрало хибну тривогу, і SSRF він після цього все одно ловить.

І два справжні баги самого DevDigest:

1. Рев'ю може піти на **порожньому диффі** і схвалити PR зі score 100, якщо
   сторінку PR перед цим не відкривали.
2. **Завислий виклик моделі** тримає прогін у `running`, доки ОС не обірве з'єднання
   (~15 хв). Таймаут SDK покриває лише заголовки відповіді, а Cancel запит не перериває.

Подробиці й докази — у `server/insights/INSIGHTS.md` і `reviewer-core/insights/INSIGHTS.md`.
